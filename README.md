# 升降杆独立调试工具

本项目用于 DS2-P/R 伺服驱动器的升降杆控制与调试，提供 JOG 点动、模式17回零、寄存器监视、手动 Modbus RTU 和目标高度定位。

仓库：<https://github.com/liuchang-t/lift-control-lab>。工作目录：`~/project/lift-control-lab`。工具与原平台独立运行，不读取或修改原平台运行配置。`baseline/` 为 OMNI-Patrol 提交 `25cfe85` 的冻结实现，仅用于模拟对照。

## 运行环境与启动

环境要求：Python 3.8 或更高版本，运行时仅使用标准库。在 WSL 中执行：

```sh
cd ~/project/lift-control-lab
python3 -m lab.server --config config.example.json
```

页面地址为 <http://127.0.0.1:8765>，服务默认监听本机回环地址。

默认模式为真实设备，启动后保持断开。页面保存连接参数后，通过“连接”建立通信；修改 IP、端口、从站或模式在下一次连接时生效，无需重启。`--allow-real` 为旧命令兼容选项，不触发连接。已保存的模拟模式优先于默认值，模拟启动可自动运行模拟器。

设备通信采用 TCP 透传完整 Modbus RTU 帧，包含 CRC，不使用 Modbus TCP 的 MBAP 报头。串口服务器应配置为 TCP 服务端和485透传模式，波特率、校验位及停止位应与驱动器一致。

## 操作入口

基础点动前点击“检查 / 恢复”，设置 JOG 速度后按住方向按钮，松手停止。JOG 不要求回零、位置可信或位于软件范围内。每次启动读取 P0D-11，值不为1时发送1，再发送17或33；速度写入 `0x4604`，单位为整数 rpm。连续点动不反复失能，松手和反向接续按正确命令应答确认。

点动方向由实际 DI 限位决定。950/952 不用于推断方向，残留警告不单独阻止点动。已知和未知报警均提供解释或原码及处置建议，不单独构成操作禁用条件。950 与“命令已应答、未检测到运动”同时出现时，提示驱动器内部可能仍在阻止运动，并建议故障复位；952尚无相同因果验证，该差异只影响诊断文案。

“使能给定 / DI观测”提供两组独立按钮：

| 按钮组 | 使能 | 失能 |
|---|---|---|
| P0D-17 / P0D-18 | 静止后写17=1、18=507 | 停止并确认静止后写17=1、18=511、17=0 |
| P03-07 | 写1并实际读回 | 写0并实际读回 |

“故障复位”只发送一次 `P0D-01=1`，随后读取 `P0B-34`。页面提示“复位前先失能”，不在复位命令前自动执行停止、失能或预检。P03-07按钮同样直接写入并读取。命令应答、寄存器给定、DI状态和实际运动分别显示。详细条件与状态变化见[显式寄存器操作](docs/control-flow.md#显式寄存器操作)。

停止接口的`stop_timeout_s`是本次请求的等待预算，不是物理减速期限。命令已应答且反馈持续有效的正常减速返回停止处理中，后台继续确认；暂未稳定不撤销位置参考。失能收尾中511已写入并读回后，后续等待从尾阶段继续，不重复507使能切换。

“停止定位”和顶部“停止”均发送 P0D-08=256，“软件急停”发送512；存在 JOG 上下文时补充撤销点动请求，并依据转速和位置确认静止。软件急停锁存通过“检查 / 恢复”解除。私有客户端共享后端，无独占控制权或租约续期要求；外部主站引起的运动仅作观测。

## 配置与坐标

配置覆盖顺序为：程序默认值 → `--config` 启动文件 → `.runtime/config.json` → `.runtime/connection.json`。页面保存值优先于示例配置，非法或损坏的保存文件报错。PP/JOG期望速度按设备身份保存在 `.runtime/profiles/`，重启加载配置，不恢复运动、使能或位置可信状态。

| 交付参数 | 数值 |
|---|---|
| 软件下限 / 收拢位置 | 1cm |
| 软件上限 / 展开位置 | 182cm |
| 行程参数 | 183.7cm |
| 控制台机械比例 L | 0.35921486cm/电机转 |
| 每转指令数 N | 10000，依据见[协议说明](docs/protocol.md) |

页面显示伸出高度，不包含安装高度或收回长度。统一换算为 `Δ计数×L/N`、`rpm=cm/s×60/L`、`cmd/s=cm/s×N/L`；整数编码采用半值远离零舍入。机械校准只修改控制台比例，不修改电子齿轮。PP和JOG分别保存cm/s及上下限，旧配置/API键 `pv` 对应JOG速度。

PP到位、收拢和展开在真实及模拟模式开放，需要可信位置参考、有效方向限位和合法目标。目标可覆盖完整软件范围，当前位置在软件范围外时也可返回范围内目标。旧配置键`max_move_pulse`仅用于后端兼容，已从页面调试JSON隐藏，不再限制候选实现的单次位移；收拢、展开使用保存的PP速度，不改为回零爬行速度。收拢、展开为软件端点定位，不用于寻找物理限位。

页面可分别保存PP加速度、减速度和急停减速度，单位cm/s²；留空沿用驱动器当前值，非空值在下次PP准备时换算后写入P10-27/29/31并实际读回。仅调整这三项及定位容差时保留当前可信参考和检查状态；重启仍需重新建立参考。

现场已验证PP定位、速度及加减速度设置、正常停止和软件急停。运动中提交新目标或点击展开、收拢会停止当前任务；检查 / 恢复后须重新手动启动，不自动接续新目标。对应方向物理限位在启动前禁止该方向，运动中触发则请求停止；950/952名称不用于确定方向。

PP参数准备完成后写P03-07=1，最后单次写P0D-08=3启动绝对定位；运动期间P0D-17保持0。到位依据P0B-04 Bit0、目标误差、转速及连续两次位置稳定共同确认，`pp_tolerance_cm`默认0.05cm，通过页面“调试参数”JSON保存。当前位置已在容差内且确认静止时不启动，状态为`already_at_target`。页面显示目标高度、位置误差及定位状态，并提供“停止定位”；未检测到运动仅显示诊断，不自动复位或锁定。定位结束复用总线运动失能收尾，详细顺序见[PP目标高度运动](docs/control-flow.md#pp目标高度运动)。

现场存在限位有效时PP反向仍拒动的情况，报警显示正确950也不能保证启动。先脱离后定位：上限位有效时只能先JOG下降，当前工具禁止HOME；下限位有效时可JOG上升或在模式17条件满足时HOME。限位警告方向错位以实际DI判断；对应DI仍有效时人工D01一次或多次曾可纠正方向，其他时机无效原因未知，不自动清警。详见[限位与恢复流程](docs/control-flow.md#限位方向警告与pp脱离操作)。

## 回零与恢复

模式17按“准备参数 → P03-07=1 → P0D-08=128”执行，运动期间保持P0D-17=0。完成判定使用本次DI过程、回零完成位、位置及转速，不要求出现950/952，不采用固定完成等待时间，也不自动定位至收拢高度1cm。

页面以cm/s设置P10-36搜索速度、P10-38爬行速度，以cm/s²设置P10-40回零加减速度；空值沿用本次驱动器读值，保存后在下次回零准备时下发。PP与正常回零收尾共用507→511切换，逐条读回并等待DI3变化；最短保持参数 `home_enable_hold_s`、`home_disable_hold_s` 默认分别为4秒、0.2秒。

601发生后，自动流程确认停止并保留报警。对已自行停止并失能且D01无效的现场情况，P0D-17/18组合使能曾使601消失，随后人工失能恢复物理DI。HOME在下限位附近曾出现掉电重启约4～5次，P10-03回到3（PV）；根因未知，需重新检查并显式回零。失能与故障复位由操作者分别执行，复位入口不附带601专用恢复流程。完整顺序见[指令流](docs/control-flow.md)，分步人工验证见[手动回零测试](docs/manual-home-test.md)。

## 监视与记录

寄存器列表按地址排序，显示寄存器自身R/W属性、实际03读回、读取策略及整秒年龄；写应答单独记录。位置、转速、DI、报警等持续采样，动态参数分组轮转，电子齿轮等固定配置按需读取。显式刷新执行实际读取，部分失败保留旧值并报告原因。负载显示有符号原码，百分比倍率尚未确认。

手动485窗口支持03/06/10及自动CRC。读取不取消普通任务；确认后的写入直接接管并取消旧意图，不附加停止、使能或复位。连接、格式、CRC及响应匹配校验持续执行。日志保留最多20,000条，支持暂停、翻页、清空和导出；内存日志在重启后清空。

页面仅展示状态、操作条件、实际结果及必要处置步骤，不设置免责性说明。详细解释放入悬停信息或项目文档。
