## 启动与正常操作

Python 3.8 或更高版本，仅标准库。建议在 WSL 中运行：

```sh
cd ~/project/lift-control-lab
python3 -m lab.server --config config.example.json
```

浏览器打开 <http://127.0.0.1:8765>，服务仅监听本机回环地址。上述命令明确使用模拟配置，不连接真实设备。未指定配置文件时会恢复本工具保存的 `.runtime/config.json`。命令行直接启动实机配置仍要求 `--allow-real`；页面切换真实设备必须显式确认后点击连接。

1. 确认连接面板为模拟模式；若已断开则点击连接。观察 P0C-13 只读检查结果，查看报警及建议。
2. 点击“检查 / 恢复”核对运行条件；它不授予操作者权限，也不等于位置参考已经可信。
3. 点击模式 17 回原点并确认。只有观察到本次回零完成、静止和正确参考后才允许普通运动。
4. 全收使用 PP 定位到回零参考上方 `soft_lower_cm`，默认 **1cm**。界面直接显示约 1cm，不另减 1cm。
5. 分别设置 PP 定位速度和 PV 点动速度，单位 cm/s。全升/全收/到位使用 PP；按住升降使用 PV，松手停止。
6. 操作被拒绝时查看固定提示区中的缺失条件和下一步。复位按钮仅在满足条件且用户主动确认后发出一次驱动器复位，不自动恢复运动。集中平台对照与故障注入不出现在操作页面，相关接口仅保留给自动回归和开发测试。
7. Ctrl+C退出。存在本后端未结束的控制任务时按停止确认流程退出；纯监视状态只断开连接，不为外部运动发送停止。网络失联时不能保证本后端停止指令送达。

默认单次 PP 位移上限约 100cm；全升目标较远时会被拒绝，需要分次定位，或在验证机械条件后修改 `max_move_pulse`。全升/全收是工作端点定位，不是每次重新寻找限位开关。HOME默认总超时600秒，另有启动/无运动保护；现场应依据全行程和实际回零速度确认超时值，不能用默认值代替验收。

## 网络串口服务器与日志

连接面板分别展示当前连接和待连接配置，可选择模拟/真实模式，编辑IP或主机名、TCP端口、驱动器从站地址与通信超时。选择模式或保存配置都不会自动连接；保存写入 `.runtime/connection.json`，点击“连接”才应用该目标，无需重启服务。真实连接必须勾选明确确认；选择真实模式本身不会发送设备报文。示例中的10.21.31.15:8899不是自动探测或已验证的现场地址。

切换连接时，若当前存在本后端的活动控制任务或停止待确认，先停止该任务并确认；若停止无法确认，保留旧连接和保护任务，显示停止待确认，不丢弃旧对象去连接新设备。纯监视状态不因设备在外部主机控制下运动而发送停止。新连接建立后只读观测，不恢复控制许可、旧运动或可信参考，需要重新检查 / 恢复和回零。切换设备/模式后的期望速度按对应身份加载。

“断开”在本后端有活动任务时先请求并确认停止；纯监视时仅停止采集并关闭连接，不发停止帧。断开期间状态和寄存器窗口只展示缓存/断开标记，读取页面不会偷偷重连，主动刷新和设备操作被拒绝；重新点击“连接”才能恢复。保存的目标和实际当前连接始终区分。

下次不带 `--config` 启动时会叠加已保存连接配置；显式启动文件优先。命令行直接选择real仍须`--allow-real`，页面运行时则由明确的真实连接确认控制。连接操作不等于运动许可；实机运动仍须完成控制条件检查。模拟切到真实设备或更换目标时不能沿用模拟验收标记。手动读写可以连接调试，正常运动仍要求既有的现场停止模型/HOME验收配置；本工具不会通过一次连接确认自动认证机械安全。

协议是TCP字节流透传完整Modbus RTU帧（包括CRC），不是带MBAP头的Modbus TCP。串口服务器侧应配置TCP服务端与485透传；波特率、数据位、校验和停止位在服务器端设置，与驱动器一致。调试台不自动改写串口服务器串口配置。

指令记录采用增量获取，服务端和浏览器活动缓冲各保存最近20,000条。默认按时间正序跟随最新；向上滚动或点“暂停”冻结当前视图，后台继续采集并显示新增数量。即使缓冲淘汰旧记录，冻结视图也不跳动；点“跟随最新”恢复显示当前缓冲。记录含递增序号和毫秒时间。暂停时“刷新”只接收记录，不改变查看位置。

“清空”清除服务端缓存和当前页记录，通信继续运行，因此跟随状态下会立即出现新记录；需要空白视图时先暂停。其他页面已有冻结快照不会被远程清除。“导出”获取当前服务端保留记录。缓存有上限且重启后清空，不是无限期审计存储；长时间测试应及时导出。

## 操作界面与恢复流程

页面采用固定状态栏和分区工作面板；操作区、寄存器表及报文记录在各自区域内滚动，操作下方按钮时仍能观察高度、速度、限位、报警和停止状态。长说明放在控件悬停提示，当前缺失条件与恢复步骤保持可见。

“检查 / 恢复”执行设备参数预检并解除故障后的运行锁定，不是权限授予，也不自动回零。私有客户端共享同一个后端，不设独占控制权、获取/释放或租约续期；不会因为一个页面长时间未操作而停止设备。一般运动仍须参数检查通过、位置可信、报警与方向条件允许。并发指令串行处理，停止优先，迟到启动不会重启已取消的任务。

| 当前状态 | 下一步 |
|---|---|
| 初次启动、重连或切换目标后 | 先确认连接，再检查 / 恢复、执行模式17回零 |
| 已断开 | 点击连接；仅保存配置或查看状态不会重连 |
| 回零成功、当前位置低于软件下限 | 等待停止确认，点击全收返回默认1cm工作端点，再使用定位或点动 |
| 回零被普通停止取消 | 位置不可信；条件允许时重新回零 |
| 回零失败 | 按显示原因排查，必要时复位驱动报警，重新检查 / 恢复并回零 |
| 人工故障复位成功 | 重新检查 / 恢复；若位置不可信，再回零 |
| 软件急停 | 等待停止确认，检查原因后重新检查 / 恢复；若位置不可信，再回零 |
| 普通停止完成 | 条件仍满足时直接发新动作 |
| 停止未确认或失联 | 等待通信与停止确认，实机使用独立现场停机措施；不可通过重复点击运动绕过 |

按住点动仍需当前动作心跳，松手、失焦或该动作保活超时停止，这是点动动作机制，不是客户端权限或租约。950/952 只有 DI 映射、极性与单侧限位明确时才可能允许反向脱离，普通运动仍须可信位置及软件范围条件；两侧同时有效或未知参考时不能提示为“直接反向运动即可”。限位已释放但报警仍锁存时，须依当前报警允许策略人工复位。

## 速度、坐标与限位

PP/PV 分别配置 `min_pp_speed/max_pp_speed`、`min_pv_speed/max_pv_speed`，配置单位 Pr/s；用户速度独立以 cm/s 保存。旧 `min_speed` 只用于旧配置迁移。非零速度超范围明确拒绝；0 表示不启动该模式，运行该模式时请求停止。实际执行速度与期望速度分别显示。

速度设置按模拟/实机、主机、端口、从站和实现类型隔离，保存在状态目录下 `profiles/`，采用原子替换。重启恢复用户速度，不恢复使能、运动意图或位置可信度。文件损坏、保存失败及恢复值越界明确报告，不能静默采用默认值。

换算沿用原项目配置：每电机转指令数 `N=10000 cmd/rev`，每电机转升降距离 `L=0.35 cm/rev`。线速度 `v cm/s` 对应 `rpm=v/L×60`、`cmd/s=v/L×N`。例如0.35cm/s对应60rpm和10000cmd/s。P10-25/42写入cmd/s，P0B-00反馈rpm，P0B-07为位置指令计数；不能把它们与编码器原生计数混用。

0.35cm/rev来自原项目机械换算配置，不能由驱动器手册证明。实机须核实实际传动比/导程及电子齿轮；P05-02为0时需要结合编码器线数与齿轮分子/分母核验每转指令数。候选关系N=编码器线数×分母/分子来自参数名称、维度和案例的一致性推导，两份手册没有明确给出该零值回退规则，不能将读回自洽或预检通过当成比例已经实测正确。详见[单位证据](docs/protocol.md)。

回零使用驱动器 HOME 模式 17，参考下限位释放沿。工具核验 HOME 原点偏移和最终反馈，不把每次最终停止位置任意当作新零点。日常坐标由该参考向上递增，全收默认 1cm，全升为 `soft_upper_cm`。普通接口不再接受任意位置“设收回零点”。

普通 PP/PV 必须有可信参考；PP 校验目标范围，PV 依据速度、允许延迟、已验证减速度和余量提前减速/停止。以下配置是保护模型的输入，**默认数字只供模拟使用，不能当作现场已验证参数**：

- `verified_deceleration_cm_s2`
- `control_latency_s`
- `limit_margin_cm`
- `motion_profile_verified`

正常控制流程对驱动器 P0A-40/41/43 与 P10-18/20 只读取显示。两组限位的关联、是否约束 PV/JOG、回零例外和触限停止行为均标为**待实机验证**，不自动写入、不计作已经验证的独立保护。网络彻底断开时，单靠上位机不能保证 PV 留在软件范围内。

## 实测修正机械比例

控制台的 `cm_per_rev` 是每电机转对应的机械升降距离，初始0.35cm/rev来自原项目。需要根据实测修正时，只调整这个上位机机械比例，不要求修改驱动器P05-02、电子齿轮或编码器参数；这些寄存器的读取用于说明换算依据及检测变化。

在确认安全工作范围、位置参考与方向正确后，使用同一方向、足够长且留有上下余量的行程，多次测量实际位移，减少传动间隙和尺读数误差。候选修正为：`新L = 旧L × 实测位移 / 指令位移`。例如按10cm移动实际量得9cm，则新L=旧L×0.9。只在停机时保存，之后重新检查并回零，再以多次测量确认修正效果；不能用一次极短位移就宣称比例已校准。

用户保存的PP/PV期望速度仍是cm/s，修正L时保留这些物理速度设置，仅按新比例重新计算cmd/s与rpm。若原速度因新比例超出配置或驱动器允许范围，明确拒绝并要求调整，不静默缩放用户速度。软件上下限仍以厘米表达，单次指令计数上限对应的厘米距离会随L变化，需要同时核对。

## 运行参数监测

高度、转速、DI、报警和EEPROM状态属于快速状态采集；单位、电子齿轮、字序、模式、目标、速度和停止相关参数属于分组扫描。扫描面板显示读取策略、风险分类和观测时间。当前分组轮转为每0.5秒最多一块、共11块，名义全轮5.5秒；实际会受总线与控制流程影响，本后端活动任务的监视参数超过12秒未完整更新会请求停止。活动模式/目标/速度另在每个保护周期核对。时间按整秒显示，但控制内部仍保留原有精度，不把界面秒数用于制动或超时计算。

参数变化需要分清来源：工具主动写入并核验的模式、目标和速度变化不应被误报成外部改动；无法与工具意图对应的变化不能自动覆盖控制基线。涉及单位、字序或位置参考的变化可能使厘米显示和保护失真；涉及模式、目标、速度或减速参数的变化可能改变运动及停止距离。本后端活动任务检测到不符时请求停止并锁定；空闲观测只提示并按风险撤销本工具的许可/参考，不发送停止去干预外部任务。

不同私有客户端共享状态与操作入口；只查看数据不会抢占、停止或修改另一个客户端发起的任务。外部主机或另一485控制端引起的位置/转速变化只作为观测，不因为“没有本工具运动意图”自动停机或使参考失效；操作员明确点击停止/急停则是独立指令。

监视不是对全部驱动参数的持续审计，也不能阻止另一主站在两次扫描之间写入。目录之外的参数、硬件输入与触发命令可能影响运动；寄存器读数与实际生效值也可能因重上电条件不同。检测延迟和通信中断必须计入实机风险，不能把“本轮未发现变化”理解成驱动器配置完全安全。

## 配置与设备参数

```sh
python3 -m lab.server --config config.example.json
```

旧`release_enable_s`只保留兼容，候选实现不执行延时自动去使能。

显式 `--config` 优先；未指定时加载本工具保存的 `.runtime/config.json`，没有文件才使用默认配置。运行中不能修改行程和保护配置；保存后需要重新预检、确认参考。设备读回值与期望配置分开显示，不自动用驱动器默认参数覆盖用户设定的工作范围。

Bridge 默认关闭。启用 `bridge_enabled` 和 `bridge_token` 后可测试集中平台入口；共享客户端不移除Bridge鉴权配置，也不自动开放公网；HOME、故障复位和维护操作仅本地开放，接口详见 [功能说明](docs/features.md)。MQTT 可发布升降状态/快照，支持用户名密码、MQTT 3.1.1 QoS0；无 TLS，不伪造机器人状态。

## 手动总线与寄存器监视

寄存器面板按当前监视目录展示地址、用途、宽度、读回值、来源及观测年龄。读回与写应答分开标记，写回显不代表已独立读回确认。未观测、过期或跨连接的值不会冒充当前状态。点击刷新读取完整可读清单；自动运动、手动接管或控制流程执行中只显示缓存，保护通信优先。

手动窗口默认开启“自动CRC”：输入从站、功能码、地址和数据，不含末尾CRC，工具按Modbus RTU算法追加低字节在前的CRC，并显示最终发送帧。关闭自动CRC后输入完整帧，原样校验发送。自动模式若检测到已带CRC的完整长度会拒绝，避免重复追加。支持当前从站的03读、06单寄存器写、10多寄存器写；拒绝广播、错误CRC和不合法长度，不改写寄存器内容、不自动重试写入。

手动读不取消自动运动。确认后的首次手动写优先接管：取消旧自动任务、确认停止，然后按编辑内容发送；不要求先点独立的“进入维护”按钮。后续手动报文可以直接操作驱动器，但不执行正常控制的软件行程/速度限制。普通运动不会与手动写交错执行。停止、软件急停、通信失效和报警保护仍优先；手动写异常或停止操作会锁定后续写入，避免迟到报文重新启动。已有报警时，明确的单寄存器故障复位报文 P0D-01=1 有受控例外，等待复位后读回；不自动延续其他写入。

结束手动会先确认停机；随后重新检查 / 恢复并回零，再全收返回工作范围。点击“检查 / 恢复”也会先结束已有手动接管。手动写可能修改使能、方向、坐标、限位或EEPROM设置；旧参考不会继续沿用。P0C-13及软限位在自动控制中保持只读，原始手动写入则由操作者明确负责，不能将工具的常规保护承诺套用到任意原始报文。

清单和具体接口见[寄存器与手动总线说明](docs/registers.md)。

## 实机入口与边界

也可从已启动的页面选择真实模式并确认连接，无需重启；以下是命令行直接选择实机配置的入口：

```sh
python3 -m lab.server --config .runtime/real.json --allow-real
```

本设备**无电机抱闸，传动系统具备自锁能力**。自锁不等于动态停止，仍需验证满载、断使能瞬间位移、停止距离和掉电保持。工具不控制不存在的抱闸；若出现抱闸相关报警，建议检查驱动器配置与型号。

启动不自动允许运动；确认现场控制条件并通过参数预检后才能发起正常运动。实机还需要验证换算、方向、HOME 参数、限位和停止模型。强制 DI 是否影响物理限位独立有效性，仍需厂家或现场确认。可只读观察其他控制端的运动；主动发起本工具运动前应协调其他控制端，避免同时向同一驱动器发送冲突任务。软件停止和软件急停不替代独立现场停机措施。

P0C-13 连接后自动读取：0 表示通信写参不更新 EEPROM；1 持续显示警告并拒绝运动预检；未知或过期不使用旧值。正常控制没有自动修改 P0C-13 的路径。维护人员可通过明确确认的原始总线写报文自行修改；工具不会替用户生成或修正此类参数写入。
