# 调试工具架构与设计决定

## 模块与边界

```text
web / HTTP / Bridge
  server.py → service.py（连接、共享客户端、接口边界）
                ├─ readiness.py（条件和恢复指引）
                ├─ manual_bus.py（手动RTU校验与写优先处理）
                ├─ registers.py（寄存器目录、读写观测与新鲜度）
                ├─ mqtt.py（状态发布）
                └─ controller.py（动作、停止、参考、报警保护）
                     ├─ model.py（配置与设备速度档案）
                     ├─ units.py（单位换算、舍入、范围）
                     ├─ alarms.py（字典与工具策略）
                     └─ driver.py（预检、采样、JOG、模拟PP/HOME）
                          └─ baseline/lift_modbus.py（基础报文编解码）
                               └─ transport.py（RTU透传/模拟器）
```

冻结基线从原代码提取适配，不导入原应用；候选复用基础报文能力，不调用旧高层运动缓存逻辑。不修改原平台及冻结证据。实机JOG采用抓包验证的P0D-11/0x4604，旧强制DI的PP/HOME仅保留模拟，不能由JOG证据推断其使能兼容性。

## 配置权威性与持久化

默认模式为真实设备，`create_service`只对模拟自动启动；真实模式仅创建未连接对象。GET状态、寄存器和保存参数不触发连接。页面明确连接后才开始采集，不恢复旧动作、使能或可信参考。已保存的显式模拟选择继续生效。

加载顺序为程序默认值 → 可选启动文件 → `.runtime/config.json` → `.runtime/connection.json`。保存值优先于示例；非法/损坏文件直接报错。页面参数保存前独立确认实际静止，不改变JOG停止只等ACK的连续操作路径。页面参数与连接配置分别原子保存，PP/JOG速度按设备身份保存cm/s至profiles，不依赖频繁写EEPROM。P0C-13在正常控制中只读，非0不能通过预检。

用户期望、驱动器读回、本次已应答命令分开。驱动器实际更宽松的限位不覆盖控制台工作范围；空闲JOG速度读回变化不覆盖用户期望或撤销检查，下一次JOG重新下发保存速度。连接变化清除旧观测有效性，不能把旧缓存作为新设备事实。

当前交付参数：L=0.35921486cm/电机转、N=10000指令单位/转，软件范围1–182cm、行程183.7cm。L依据两点实测只修改控制台换算，不写电子齿轮。`units.py`统一位置、速度、整数半值远离零舍入；前端不另存导程或换算常量。改变L保留用户cm/s设置，越界明确拒绝，不静默缩放。

N必须与驱动器实际有效单位一致。P05-02=0时“编码器线数×分母/分子”是与案例及现场读数自洽的候选关系，手册未明确零值回退规则；读回一致不等于固件行为或机械比例已证明。负载P0B-02倍率不明，保留uint16原码与int16解释，不以百分比包装未知单位。

## 动作与并发

普通控制串行，stop/estop先取消意图、增加命令代次；发送前再次检查代次，避免排队旧启动在停止后执行。相同停止周期合并前台等待和后台重试，旧intent的松手不停止新动作；急停仍全局生效。共享私有客户端没有获取/续租门槛，旧lease接口是兼容无操作。

JOG每次读取P0D-11，非1才发1使能，再发送17/33。P0D-17保持0以保留实际限位输入；0x4604是整数rpm。本次启动重新写速度，活动期间独立核对。普通停止发1保持使能，命令应答后正反方向均可再启动，不等待实际静止，不执行旧 `release_enable_s` 延时失能。独立失能/急停发65。正确应答表示设置成功，不能证明功率级完成或机械停稳。

点动心跳绑定本次动作，不能重新启动已经结束的动作。无运动只生成诊断，不判定堵转、不撤销检查或停止；存在950时提示驱动器可能仍阻止运动，建议用户松手并人工复位，952不作此推断。驱动器故障、实际方向限位、松手和通信保护独立执行。

纯观测不因外部主机启动运动而自动停止或撤销参考。显式停止仍是用户控制指令。本工具活动任务中出现通信/参数异常请求停止，失败保持未知并重试；不能将请求已发或主机超时表述为设备已停。

## 参考与三类边界

设计上的包含关系为机械端点在最外层、物理限位开关在其内、日常软件范围更靠内。机械端点不能作为无损停止手段。设备无抱闸、传动自锁，但自锁不是动态制动证据。

模拟HOME模式17参考负限位释放过程，要求本次运行/完成证据、最终静止和原点偏移核对；不将任意停下的位置重定义为零。取消、超时或异常不建立可信参考。全收使用该参考上方1cm，普通接口不提供任意人工设零。

模拟PP需要可信参考，校验目标、方向、报警和单次位移。当前位置在软件范围外不妨碍返回范围内目标；全收/全升是快捷端点，普通到位使用保存的PP速度。基础JOG不依赖软件位置模型，只按物理DI约束方向。P0A/P10驱动器软限位只读，覆盖模式、HOME例外和触限行为仍待实机验证。

## 报警与恢复

报警字典保存原始值、归一化码、手册名称、类别、复位标注、建议和来源；控制策略独立于手册“警告”分类。

基础JOG对950/952以实际DI决定方向：两侧正常允许双向，单侧触发只许反向，两侧或信号不明禁止。警告本身不撤销检查，兼容下限位报950。其他非零故障保守阻止新动作并停止本工具活动任务，参考类故障使参考失效。模拟PP/HOME保留各自更严格策略。

人工故障复位为明确操作：停止后确认原因已处理，按允许策略单次写P0D-01=1并读报警；不自动复位或续发旧运动。仅清除950/952成功且此前检查有效时保留该状态，不解除原有急停/其他锁定、不建立参考。其他故障复位后需检查 / 恢复。未知或不可通用复位的码不能套用普通复位。

## 观测与保护采样

快速状态包含位置、速度、状态字、DI、报警、P0C-13及相关JOG命令/强制输入观测。动态参数轮转当前为5块，每0.5秒最多一块、名义全轮2.5秒，控制事务优先；活动任务适用的动态扫描超过12秒未更新请求停止。活动PP模式/目标/速度、HOME参数及JOG速度另按保护周期核验；无关P10参数不阻塞基础JOG。

固定的编码器、每转指令数、齿轮、方向、字序、DI配置等在连接、预检、动作准备或手动刷新时读取，不周期重复读取。外部修改这些固定参数不能即时发现；两次轮询之间发生并恢复的改变也可能遗漏。无任务时只更新诊断及必要的参考/检查状态，不停止外部运动。

`RegisterMonitor`采集真实事务结果。双字只组合相同事务和连接内完整值，硬件R/W与工具是否写入无关；P0D-11保留独立读回和写ACK，主值只用读回。新鲜度匹配读取策略，按需项不因短暂经过几秒就过期，跨连接失效。UI显示整秒，内部仍用精确单调时钟。运动期间完整刷新只返回缓存，避免延迟保护。

## 连接、手动总线与界面

当前连接和待连接目标分离，编辑/保存不改变当前通信。切换/断开遇本工具活动任务时先停止；失败保留旧对象和保护任务，不伪装断开。纯监视只关闭连接。真实模式每次显式连接需确认；`--allow-real`不能触发自动连接。

手动接口复用同一串行传输，不创建第二个连接。03读取不取消运动；首次确认06/10写取消旧动作，完成停止后发原始帧。普通启动不穿插手动写；写结果不确定不重发原报文，停止保护仍有效。原始写撤销参考，退出后重新检查。其任意寄存器内容不能纳入普通软件范围保证，明确的人工P0D-01复位帧有受控报警例外。

`readiness.py`提供可见缺失条件与下一步，命令执行仍独立复核。固定状态栏与独立滚动面板避免操作时看不到状态；说明放悬停，当前拒绝/恢复步骤直接显示。无运动950建议随条件消失清除，物理限位提示随有效反馈脱离清除，历史日志不删。

## 验证与残余风险

模拟测试证明软件分支、取消顺序、报文和配置恢复，不证明满载停止距离、机械冲击、断电自锁或实际断网停机。尚无明确功率级使能完成位和RS485断链自动停机依据。实机PP/HOME兼容、驱动器软限位、950/952固件差异等见[验证边界](validation.md)。这些是能力边界，不新增验收或权限门禁。
