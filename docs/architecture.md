# 系统架构与设计约束

## 系统范围

独立调试工具负责升降杆控制、驱动器观测和手动RTU通信，不加载原平台服务或运行配置。`baseline/`保存原平台冻结实现，候选控制器复用其中的报文编解码，不复用原高层运动缓存逻辑。冻结实现仅用于模拟对照。

真实设备使用P0D-11及0x4604执行JOG，模式17HOME采用P03-07给定后启动。PP采用参数准备、P03-07使能和绝对启动3，在真实及模拟模式开放。功能与接口见[功能说明](features.md)，详细寄存器序列见[控制流程](control-flow.md)。

## 模块职责

```text
web / HTTP / Bridge
  server.py → service.py
                ├─ readiness.py
                ├─ manual_bus.py
                ├─ registers.py
                ├─ mqtt.py
                └─ controller.py
                     ├─ model.py / units.py / alarms.py
                     └─ driver.py
                          └─ baseline/lift_modbus.py
                               └─ transport.py
```

| 模块 | 职责 |
|---|---|
| server / service | HTTP/SSE、连接生命周期、配置更新、客户端与Bridge接口 |
| controller | 运动意图、停止确认、位置参考、报警观测、显式寄存器操作 |
| driver | 设备预检、采样、JOG、HOME、PP及共用失能收尾 |
| transport | 串行RTU透传、连接代次、模拟驱动器 |
| registers | 寄存器目录、R/W属性、实际读值与写应答缓存、新鲜度 |
| units / model | 单位换算、整数舍入、配置验证、设备速度档案 |
| alarms / readiness | 报警解释、处置建议、操作条件与恢复步骤 |
| manual_bus | 原始RTU帧校验及手动写接管 |
| mqtt | 可选状态发布 |

## 配置与持久化

配置优先级为程序默认值、启动文件、`.runtime/config.json`、`.runtime/connection.json`，后者覆盖前者。页面配置和连接目标分别原子保存；PP/JOG期望速度按设备身份保存于profiles。非法配置或文件损坏报错，不回退为示例值。

默认真实模式启动只创建未连接对象。读取页面状态、读取缓存、保存连接目标不建立设备连接；显式连接后才开始采集。模拟模式可自动启动模拟器。重启不恢复运动、使能或位置可信状态。

用户期望值、驱动器实际读值及写应答分别保存。空闲JOG速度读回变化不覆盖用户期望；新JOG重新下发保存速度。参数保存前独立核对静止，不改变普通JOG松手的ACK确认路径。仅修改PP三项加减速度及定位容差时保留现有位置参考与检查状态；其他配置变化沿用参考撤销流程。PP三项加减速度采用可空的cm/s²配置，下一次PP准备阶段通过统一单位模块换算为cmd/s²并写后读回，空值不写对应寄存器。

`units.py`统一厘米、rpm、指令单位及整数半值远离零舍入。当前交付参数为L=0.35921486cm/电机转、N=10000、软件范围1～182cm、行程183.7cm。改变L保持用户cm/s期望值，换算后超界则报错。校准只改变控制台比例，电子齿轮由驱动器实际读值核验。

## 控制意图与并发

普通启动序列使用控制器顺序锁；单帧通信使用传输锁。停止或新接管操作先增加意图代次，发送前再次核对代次及连接，取消尚未发送的旧命令。已发送的事务等待响应或超时，后续事务继续串行。

同一停止周期合并前台等待与后台重试。点动松手携带intent_id，旧动作的迟到松手不终止新动作；顶部停止及软件急停使用全局路径。共享客户端无独占租约，旧lease接口保留兼容行为。

JOG每次读取P0D-11，非1才发送1，再发送方向17/33。速度写0x4604，单位rpm。松手停止保留使能，按正确应答确认，正反方向接续不等待实际静止。页面心跳只延续本次动作，旧心跳不能重新启动。无运动提示不触发JOG锁定或自动停止。

顶部停止与软件急停固定发送P0D-08=256/512；有JOG上下文时补充撤销点动请求，再以转速和位置确认静止。失败保留待确认并在停止恢复路径重试；PP区域“停止定位”复用该全局正常停止及静止后的共用收尾。pending_stop期间拒绝新普通运动，但不拦截独立按钮的人工介入。纯观测状态下，外部主站引发的运动不触发自动停止或参考撤销。

`stop_timeout_s`限定停止接口的等待预算，不限定驱动器的物理减速时间。命令已应答、反馈新鲜且仍处于STOPPING时，预算结束返回pending状态，后台继续确认，不因正常减速未结束返回503。`StopNotSettled`只表示静止条件尚未满足，保留位置参考和停止任务；通信或参数异常仍按各自错误路径处理。

## 显式寄存器操作

`Controller.operator_write`统一处理故障复位及P03-07按钮：取消旧自动意图和保活，取得顺序锁，执行单次写入，随后实际读取结果。该路径不插入停止、失能、预检或运动启动。

| 动作 | 写入 | 结果读取 |
|---|---|---|
| reset_fault | P0D-01=1 | P0B-34 |
| servo_p03_enable | P03-07=1 | P03-07 |
| servo_p03_disable | P03-07=0 | P03-07 |

连接有效且未切换时，这些动作不依赖报警、反馈新鲜度、检查状态、手动接管或停止待确认。软件急停锁存不阻止显式写入，也不被写入解除。后续停止或连接变化仍可取消尚未发出的旧命令。

写应答、读回值和读回错误分别记录于`operator_result`。报警未清除或给定读回不一致时报告实际值，不自动重试。空闲有效检查状态可保留；打断活动任务时不自动恢复任务，打断HOME时取消本次参考。已知参考失效报警仍影响位置可信度。

P0D-17/18按钮先取消旧收尾意图，再执行自身的停止、实际静止确认及多步写读序列，不调用旧完整收尾作为前置条件。P03-07及故障复位仍采用直接单写，不等待静止。全部人工入口保留软件急停锁存，不自动恢复运动。P03-07、D01及P0D-17/18接管同时撤销旧bus_enable_owned，停止旧收尾的自动管理；该状态变更不确认实际功率级失能，后续JOG不会自动续跑被中止的收尾。

## 位置参考与限位

机械端点、物理限位开关、软件工作范围从外到内设置。基础JOG使用实际DI方向限制，不依赖软件高度。PP要求可信参考、合法目标和实际方向限位，允许从软件范围外返回范围内目标。历史max_move_pulse仅保留后端配置兼容，页面调试JSON中隐藏，候选实现不再据此限制单次行程。

现场运行约定与软件方向检查分开：限位有效时，驱动器可能应答反向PP启动但不运动，先脱离限位再使用PP。上限有效时当前HOME也拒绝启动，只能先JOG下降脱离；下限有效时可JOG上升，模式17HOME仍按现有启动条件执行。这是人工操作策略，不增加报警门禁或自动复位、自动脱离流程。

模式17HOME以本次完成位、实际下限位过程、位置及静止建立参考。取消、超时或失败不建立参考；正常完成不自动移动至收拢1cm。成功或非601的中止流程在满足静止条件且仍持有HOME使能时执行失能收尾；601自动停止保留报警，不执行可能清警的收尾。

PP与HOME通过`release_bus_enable`共用失能收尾，`bus_enable_owned`记录当前工具的总线使能请求。`release_home_enable`及原HOME所有权入口保留兼容。共用流程包含逐条读回、DI3条件等待、最短保持及意图取消检查。最短保持默认4秒和0.2秒，继续使用`home_enable_hold_s`、`home_disable_hold_s`配置键。这是HOME现场验证采用的配置，非厂家完成时限；PP正常定位与停止收尾已有现场结果，任一限位有效时不能依赖PP反向脱离，内部原因仍未知。其他停机生效参数可参考同一失能过程，但当前未提供通用自动改参器。

共用收尾在511写入并实际读回后记录尾阶段。DI3、最短保持及退出强制DI完成后若位置或转速尚未稳定，继续从尾阶段确认，不重新发送507。退出强制DI的读回仍不等同于实际功率级失能反馈。

PP准备在静止后检查bus_enable_owned及本次P03-07读值；任一表示已有给定时先执行共用收尾，601保留导致False时不继续自动启动。随后核对方向、总线极性、原点偏移及PP运行参数，以本次读值建立启动条件。该准备路径不改变已有JOG控制路径。

PP完成状态独立记录目标、误差和驱动到位反馈。stopping表示停止及收尾中，cancelled不等于实际静止，stopped表示静止已确认，complete要求到位及收尾完成。601保留时使用stopped并说明未执行失能收尾。`pp_tolerance_cm`默认0.05cm，由统一配置保存和加载；完成判据为Bit0、位置容差、低转速及连续两次稳定反馈。无运动只生成诊断。已在容差内且确认静止的请求返回`already_at_target`，不启动运动。

## 报警策略

报警字典保存原始码、归一化码、手册类别、复位标注、解释、建议及来源。已知或未知报警不单独禁止人工使能、失能、普通运动请求或故障复位。手册复位属性用于说明，不作为按钮白名单。

950/952不能确定实际限位方向，启动与运行方向保护取实际DI。两种警告均有与DI方向不一致的现场记录；JOG的950无运动诊断与PP在有效限位下拒动属于不同观察，不据报警名称推断驱动器内部原因。已知参考失效报警撤销参考，未知报警不推断参考丢失。HOME收到601时结束失败任务；故障复位不自动续发任务或解除软件急停。

## 观测与通信

快速采样读取转速、位置、状态、DI、报警、P0C-13以及DI3配置和JOG/强制输入给定。动态参数5块轮转，每0.5秒最多一块，名义全轮2.5秒。活动PP的轮转变化比较及12秒失鲜保护均只覆盖PP模式、目标及0x1017最大速度/PP速度/加减速参数块，无关HOME或0x4604变化、旧龄不触发停止；HOME、JOG另行核对各自活动参数。

电子齿轮、字序、方向及DI4/DI5功能等固定配置按需读取，外部改动在下一次相关检查时发现。`RegisterMonitor`保留真实03读值及独立写ACK，双字仅组合相同事务、相同连接的完整数据。显示年龄为整秒，内部使用单调时钟。

显式刷新逐块读取并在块间让出总线，运动或接管期间也可执行。部分错误保留原读值和时间，返回成功数量及错误列表；连接变化取消刷新。断开不隐式重连。

## 手动RTU与连接生命周期

手动接口复用当前串行连接。03只读不取消任务；确认后的06/10直接接管，取消旧自动意图，不附加停止或其他命令。接管期间报警、失鲜和通信错误用于诊断，不自动插入控制帧或重发原始写。用户主动停止、退出接管和连接切换仍取消旧排队请求。

原始手动写撤销普通位置参考；退出接管后重新检查，PP另需重新建立参考。格式、CRC、从站、响应匹配与连接身份始终校验。当前连接和保存目标分离；切换遇本工具活动任务时先停止，失败保留旧连接及待确认状态；纯监视直接断开。

## 界面与文档

界面展示状态、操作条件、下一步和实际结果，固定顶部状态及停止入口，各区域独立滚动。说明优先放入悬停信息；不设置免责性说明。诊断提示随条件消失清除，历史日志保留。

[实测记录](drive-behavior.md)维护硬件证据，[验证状态](validation.md)区分已执行测试和未验证事项。实际使能完成反馈、RS485断链停机、PP有效限位拒动原因、HOME下限附近掉电重启原因及软限位覆盖仍待核实；未知行为不转化为新增权限或验收条件。
