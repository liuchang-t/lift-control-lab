# 运动指令流与通信故障处理

所有数值为十进制，参数后的地址为十六进制。此处描述独立候选工具的正常控制，不适用于任意手动原始写入。

## 共同准备

检查本工具运行条件、可信位置（HOME除外）、报警、方向限位、目标和速度；切换已有任务先停止并确认静止。重新读取单位及分组运行参数，与已检查基线比较。

PP/PV顺序：P0D-08(0D08)=0 → P0D-18(0D12)=511去使能 → 等50ms → 读P0B-07当前位置并写P10-14对齐旧目标 → 读取P02-00(0200)，非9才写9 → P10-03(1003)设模式 → 写对应速度 → P0D-17(0D11)=1 → P0D-18=507使能 → 重新采样检查报警/限位 → PP写最终目标 → 发启动。

模式、目标、速度等普通参数写后独立读回比较。P02-00读取/条件写入由PP/PV/HOME共用，避免重复写9可能被驱动器拒绝。其它普通运行参数当前仍可能重复写入；触发寄存器绝不因历史值相同而省略发送。

|按钮|模式和参数|最后启动指令|结束条件|
|---|---|---|---|
|按住上升|P10-03=3，P10-42=PV速度|P0D-08=16|松开、心跳失联、保护停止|
|按住下降|P10-03=3，P10-42=PV速度|P0D-08=32|同上|
|到位|P10-03=1，P10-25=PP速度，P10-14=输入高度换算目标|P0D-08=3|目标误差≤20指令单位且转速≤1rpm，随后确认停止|
|全收|同PP，目标为软件下限，默认1cm|P0D-08=3|同PP；回零后低于下限返回时速度不超过HOME爬行速度|
|全升|同PP，目标为软件上限|P0D-08=3|同PP|

## 模式17回零

先读回零方式、偏移、搜索/爬行速度、加速度、最大速度；当前方式必须已是17，偏移必须与工具配置一致，速度必须有效。不会擅自覆盖其它回零方式。

清控制字0 → 去使能511 → 等50ms → 检查P02-00，必要时写9 → P10-03=6 → P10-35(1023)=17 → 强制DI选择1 → 使能507 → 再采样检查 → P0D-08=128触发。HOME速度、加速度、偏移沿用读取并核验的当前值。

后台必须观察本次未完成→完成，限位释放，位置与预期参考相符及连续稳定反馈，才能建立可信参考；然后请求停止并确认。并不是收到128的应答就算回零成功。

## 等待与确认

总线锁确保单个RTU请求等待完整应答后才发下一个。校验CRC、从站、功能码、长度、异常码、写回地址/值或数量；默认单事务超时0.5秒。TCP传输每次应答后留5ms间隔，去使能后另等50ms。该间隔不是已验证的任意波特率保证；实际串口帧间隔及服务器缓存/转发策略须现场核对。

参数写后读回一致才继续。P0D触发寄存器只确认ACK，动作效果靠后续状态/转速/位置确认；目前未对SON/OFF建立独立完成位等待，因此50ms是否足够须按驱动固件验证。

每个步骤前后检查任务取消代号；停止会作废旧任务，避免准备过程结束后继续迟到启动。启动命令不自动重发。收到异常或超时即退出当前序列；超时视为结果未知，不能据此认定设备没有执行。

## 故障表现和恢复

准备/启动失败会显示启动未确认、故障或运动状态未知，撤销检查状态，后台请求停止。停止为P0D-08=256，软件急停为512；读取两次反馈，中间至少60ms，要求两次转速≤1rpm、位置变化≤20指令单位。未确认则继续重试，显式停止默认等待3秒后返回停止未确认，后台仍重试。

用户应先确认设备实际停止；链路中断且设备仍动时使用现场独立硬急停。排查连接/驱动报警，重新检查；参考失效或回零失败须重新回零。人工故障复位只用于驱动报警，不是网络超时的通用处理。不会自动恢复运动。

## 两段通信的边界

- 浏览器点动每300ms保活，松开/失焦/离页主动发停止；默认1秒未收到当前意图心跳，后端请求停止。首次运动窗口从启动确认后计算。旧意图不能重新启动；网络延迟仍可能在后端知道松开之前产生短暂运动。
- PP和HOME是后端独立任务，不依赖页面保活。浏览器断线后仍可继续到位/回零，后端继续保护；不因其它观察客户端掉线而干预运动。HTTP响应丢失不代表请求未执行；PP/HOME目前没有通用请求去重键，结果未知时应先查询状态，不能盲目重复提交。
- 反馈采样默认每轮后间隔0.2秒，实际周期含各RTU往返。活动任务反馈超过1秒延迟预算、报警、限位、参数异常、堵转等会请求停止。低频参数12秒未完整更新也触发本工具任务保护。
- 串口链路完全失联、后端进程退出或主机断电时，软件无法保证停止命令抵达。当前未实现经过实机核验的驱动器通信看门狗；PV可能持续运行，PP/HOME也可能继续。不能将1秒检测预算等同于1秒内机械停止。物理限位、独立硬急停及已验证的驱动器失联策略是此边界的兜底。
- 外部主机发起的运动在纯观察状态下不被本工具自动干预。

## 使能完成与通信超时：手册证据边界

核验来源为现场提供的《DS2-PR用户使用手册26-9-4.pdf》和《DS2-PR 485串口案例.pdf》。下列页码区分PDF页序与印刷页码，已检查完整页面表格。

|问题|明确证据|实现结论|
|---|---|---|
|P0B-04是否报告使能完成|用户手册PDF第18页（印刷16页）仅定义Bit0位置到达、Bit1速度到达、Bit2转矩到达、Bit3回零完成|没有已定义的SON/伺服功率级开启或关闭完成位；不得套用其他伺服协议状态字|
|S-RDY能否当使能完成|用户手册PDF第10页（印刷8页）FunOUT.1含义是伺服准备好、可以接收S-ON有效信号|准备接收使能不等于使能已完成，也没有明确说明S-OFF后该信号必须撤销|
|DI/DO读回能否代替|P0B-03报告DI1~DI6，P0B-05报告DO1/DO2；P0D-17/18定义强制DI与给定|DI输入或强制给定不是功率级反馈；手册没有明确P0B-03取物理输入还是强制后的有效输入。DO还依赖P04功能与极性，不可擅自改映射用于完成判断|
|等待时间是否可从参数推出|用户手册PDF第13页（印刷11页）P02-18是S-ON滤波0~64ms；P02-09/10是抱闸相关延时|滤波时间不是完整使能转换耗时上限；不能把读到该参数后等待同样时间当作完成。现场无抱闸，也不能据此推定内部状态切换瞬时完成|
|驱动是否支持RS485断链自动停机|用户手册PDF第19页（印刷17页）完整P0C表未列出失联检测时间、动作或喂狗机制；P0C-25为指令应答延时0~5000ms|未找到可实现的配置依据，不代表硬件必然不支持；不尝试未公开地址，不把P0C-25写成停机超时|
|案例中的超时处理由谁执行|串口案例PDF第11页说明驱动未收正常报文或检测到错误时不返回，由主机进行超时处理|这是主机应答等待处理，不是驱动器在主机消失后自行停止的保证|

本次结论：没有可明确实现的使能完成状态位等待或驱动器通信看门狗配置。控制代码不新增猜测状态位、未知寄存器写入、自动DO重配置或未经确认的失联动作。现有ACK检查、参数读回、停止运动反馈确认继续有效，但都不能证明伺服功率级已开启/关闭。原50ms准备间隔仍只是既有等待，未被本次核验认可为完成判据；不能宣称已完成闭环使能握手。

P0B-04的“位置到达”、零转速、电流为零以及P0D写回值，均不能用作“去使能完成”的替代证明。通信完全中断时，也不能依赖上位机重发停止来保证驱动已停止。

后续实现所需厂家信息：与现场固件对应的使能/功率级完成状态地址、位定义、ON/OFF极性和适用模式；强制DI与滤波/状态监视的关系；RS485看门狗寄存器、计时单位与范围、哪些报文刷新计时、断链后动作（减速/急停/去使能）、适用PP/PV/HOME模式、上电默认及复连是否自动恢复。获得明确资料后再实现并进行断链和状态转换实机验证。

## 强制DI给定核对的实现

正常PP/PV/HOME流程和故障复位去使能路径，在写P0D-17/18后独立读取0x0D11起两字及DI3观测，要求本次写入地址的读回与给定一致才继续。失败中断，不重发启动；现有状态机负责停止确认和恢复提示。其余P0D触发命令仍按ACK与动作反馈分别处理，不被此规则误作保持值。

这是给定存储值核对，未实现使能完成握手，也未替代既有准备间隔。每轮状态采集追加一条两字读请求，复用已有DI采样；写后核对另读DI3用于记录前后状态。实机读支持、寄存器保持行为与新增通信耗时需验证；若读回不支持则明确失败，不降级为仅凭ACK通过。

## 独立使能与失能

页面使能给定区域提供“使能”“失能”，对应普通控制接口的servo_enable/servo_disable。无需先回零，操作不会授予正常运动检查状态，正常运动仍需检查/恢复和必要的回零；当前手动接管期间先结束手动，再使用这两个正常流程按钮。

两者首先取消旧运动意图并发送停止，通过现有两次静止反馈确认。使能在本后端任务运行/准备、停止待确认或软件急停锁定时拒绝。失能允许在运动中请求，立即取消旧任务；停止未确认时不写强制DI给定，保持停止重试。

静止确认后读取DI3功能/极性，必须是S-ON且低电平有效。使能另要求无驱动报警；失能不因驱动报警被拒绝。清除P0D-08旧控制字，先写并核对P0D-18=511，再写并核对P0D-17=1，避免启用强制DI时旧507给定突然生效；使能最后写并核对P0D-18=507，失能保持511。不写位置/速度目标，不发送PP/PV/HOME启动码。停止或连接变化可取消未完成序列，不能因读回晚到再补发使能。

独立操作成功后取消普通运动检查状态；位置参考如未因回零中断/失联等原因失效则保留，不主动重新标定。按钮反馈只确认给定读回，不声称功率级切换完成。停止确认函数由普通停止和独立按钮共用；链路失效仍不能保证实际停止。

## 点动保活与页面负载

点动准备完成、启动响应返回后，页面才开始300ms保活；同一时刻最多一个心跳请求。松开、失焦或离页取消保活并发送停止；收到保活拒绝或网络错误时结束本次按住意图，只提示一次，必须松开后重新按下，不自动重启。准备期间松开仍发取消停止，迟到启动响应不能重新创建保活计时器。

后端1秒默认保活阈值不放宽。保活超时停止记录明确reason，状态快照stop_reason以及后续拒绝返回该原因，避免统一“旧保活”掩盖实际原因。页面日志保存20,000条历史但采用有界分页显示，避免一次格式化全部历史阻塞主线程并拖延心跳。
