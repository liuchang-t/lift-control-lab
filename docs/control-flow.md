# 运动指令流与通信故障处理

## 基础JOG

基础点动采用官方软件抓包证据，P0D-11地址为 `0x0D0B`，P0D-17保持0。旧API/保存键 `pv` 对应JOG速度，不使用P10 PV启动。

| 操作 | 指令 | 命令成功判据 |
|---|---|---|
| 使能 | P0D-11=1 | 正确写应答 |
| 上升 / 下降 | P0D-11=17 / 33 | 正确写应答 |
| 点动松手停止 | P0D-11=1，保持使能 | 正确写应答，不等待静止 |
| JOG内部撤销使能 | P0D-11=65 | 正确写应答；顶部急停另发送总线512 |
| JOG速度 | 0x4604，单字整数rpm | 正确写应答，活动采样另行核对 |

每次新点动执行：

1. 检查连接、检查状态、新鲜反馈及实际DI方向条件；报警只显示和记录；无需回零、位置可信或软件范围。
2. 仅当本工具仍持有未清理的HOME使能时，先完成该HOME清理；普通连续点动不因读到P03-07=1而发送总线停止或修改DI3极性。确认P0C-13=0。读取P0D-17/18；若P0D-17非0，解除为0并读回核对，不能强制DI为1。P0D-18不是新的使能通道。
3. 按保存的cm/s通过统一换算得到整数rpm，写0x4604。每次启动均写入，不采用空闲时回落的速度覆盖用户值。
4. 读取P0D-11；若不等于1则写1使能并检查应答；等于1可省略该写入。不依据历史ACK跳过读取，不先写65。
5. 重新采样核对实际限位和强制DI来源，再写17或33，校验应答。各步骤检查动作代次，已经松手或被新意图取消就不继续启动。

相邻事务等待前一条正确应答后才继续。应答检查CRC、从站、功能、长度、地址和数值；失败终止启动并进入异常/停止处理，不靠固定延时推定成功。P0D-11读回和写ACK只表达命令层信息，均不证明功率级使能完成。

保持按住时，页面约每300ms为同一intent发送心跳；后端约每1秒续发当前方向，仅延续有效动作。松手、失焦、隐藏或保活超时请求停止；心跳不能重启已结束动作。该续发行为不是已经验证的驱动器断链看门狗。

## 停止、连续操作和无运动

松手先取消旧意图。已使能JOG发送1保持使能；已明确失能或尚未使能时用65，避免单纯停止反而使能。收到正确应答即可新点动，正反向均不等待零转速/位置稳定；显式切换方向先停止并等ACK，再发新方向。不执行延时自动失能。

重复停止、前台等待和后台重试共用结果；旧intent迟到松手不会打断新动作。顶部停止始终发总线256，急停始终发512，并撤销当前JOG请求；同一停止周期收到正确应答后不重复发送，失败则保留待确认。急停不受旧intent限制。停止应答未知时保持待确认并重试，不伪装已停。独立“使能”按钮在静止后依次执行P0D-17=1、P0D-18=507，并保持强制DI；独立“失能”按钮先停止并确认实际转速/位置静止，再依次执行P0D-17=1、P0D-18=511、P0D-17=0。每步复用强制DI写入/03实际读回核对，正确才执行下一步，不以后台轮询或写回显替代；失败中止当前序列并进入停止待确认。按钮不发送JOG使能命令，不启动运动；不改变基础JOG或HOME自身的使能方式。给定读回一致不证明功率级完成。

命令已应答但未检测到运动只显示诊断，不判定堵转、不停止、不要求重新检查。若同时有950，提示“可能是驱动器内部仍在阻止运动”，建议松手、停止应答后人工故障复位，再手动点动；不自动复位。952未验证，不套用950结论。恢复运动、动作结束或950消失即清除对应建议。

## 限位、报警和恢复

DI4/DI5的功能/极性决定实际上下限位。950/952不用于猜方向，也不单独锁定基础JOG：两侧正常可双向；单侧触发只许反向；双侧同时触发或信号无效禁止。下限位报950也遵循这条规则。限位停止提示在新鲜有效反馈确认脱离后清除。

报警码（包括未知码、过载等故障）用于展示与建议，不再单独禁止操作者使能、失能、点动或定位，也不自动撤销检查状态。通信异常、实际物理限位、强制DI异常和活动JOG速度不符仍按各自保护处理。完整报警字典及建议见[协议文档](protocol.md)。人工故障复位需要用户操作、停止及条件检查；需要驱动复位时只发一次P0D-01=1再读报警，不自动运动。601保留至人工处理，失能已使其清零时不再发送复位。单纯清除950/952成功保留此前有效检查；601清除后在同次人工操作内重新检查，其余故障及软件急停按恢复指引处理。复位不建立位置参考。

## 模式17一键回零

HOME采用用户已成功执行的手动顺序：先准备参数，再使能给定，最后启动。当前版本已获操作者功能测试通过反馈，专项边界见验证文档。

1. 核验反馈新鲜、P0C-13=0、实际DI有效，并显示当前报警供操作者判断；950/952不按文字猜方向，也不要求必须出现。确认P0D-17=0、DI3功能为1、原始DI3高电平。P03-07是DI3极性配置，不是独立的功率级完成反馈。
2. 先通过实际转速与位置确认静止，再依次写P0D-08=256、0清除旧总线请求，并写P03-07=0准备DI3极性（不据此宣称已经失能）。准备P02-00=9（已为9时无需重复写）、P10-03=6、P10-35=17；按页面保存的期望配置准备P10-36搜索速度、P10-38爬行／查询速度和P10-40回零加减速度：填写项逐项写入并实际读回；留空项沿用本次读取值（P10-36仍按原流程重新写入）。P10-16偏移只读取核对，不自动改写。每步核验正确应答/读回，不用固定延时替代确认。
3. 写P03-07=1并独立读回，再复采实际DI、报警及控制条件；最后仅一次写P0D-08=128。不能先128后使能，不使用P0D-17=1，也不把P0D-11历史ACK当作HOME使能。
4. 观察寻找下限位、触发后减速/脱离、最终稳定阶段。下限位已触发的起点允许驱动器直接脱离；不要求看到950/952，不把下限位信号当作需要立即终止HOME的普通点动限位。异常上限位、通信异常、超时或明确601回零失败进入结束/停止流程；其他报警码不单独作为运动门禁。
5. 用本次启动后的完成位变化、实际下限位过程、位置与配置参考吻合以及转速/位置稳定共同确认成功。历史完成位、瞬间零转速、固定7.8秒均不能代替完成证据。取消或失败不建立可信参考；成功也不自动PP移动到软件下限1cm。

### HOME静止收尾与实验性保持

正常成功HOME运动期间保持P0D-17=0。停止命令应答后，以转速和位置反馈确认静止，再自动执行以下收尾。若当前为Er.601，自动停止仅确认静止，不执行可能使报警消失的强制DI收尾，具体见后文人工恢复。每条写入均校验应答并以03实际读回核对，成功才进入下一步；P03-07写回0本身不能证明实际失能。

| 顺序 | 写入与观察 | 继续条件 |
|---|---|---|
| 1 | P0D-08=0、P03-07=0 | 分别读回一致 |
| 2 | P0D-17=1 | 读回1 |
| 3 | P0D-18=507 | 读回507，再读取P0B-03 Bit2直到DI3=0 |
| 4 | 保持507 | 最少保持home_enable_hold_s，默认4秒；保持期间持续核对给定、DI3、转速和位置 |
| 5 | P0D-18=511 | 读回511，再读取P0B-03 Bit2直到DI3=1 |
| 6 | 保持511 | 最少保持home_disable_hold_s，默认0.2秒；同样持续核对反馈 |
| 7 | P0D-17=0 | 读回0，最终确认P0D-17/18为0/511 |

每个DI3条件等待阶段使用stop_timeout_s作为超时上限（默认3秒），条件满足即结束该等待；它与随后独立的最短保持阶段不同。两个保持时间均为用户允许的实验参数，不是厂家规定时限或实际使能/失能完成判据。可在页面“调试参数”保存home_enable_hold_s与home_disable_hold_s（0～10秒），重启继续生效；设为0仅取消相应最短保持，不取消读回和DI3条件核对。

507/511的输入观测到位、保持时间结束、最终给定读回均不证明功率级失能。现场已出现DI3先0后1而自动收尾仍未实际失能；手动分开点击使能/失能可恢复，4秒/0.2秒保持方案已有一次由操作者确认自动失能的现场结果，当前版本随后获得各功能测试通过反馈。不同工况重复性仍需独立核验，不能仅凭模拟或最终P0D-17=0认定实际失能。

读取失败、读回不一致、DI3等待超时、保持期间给定/DI3改变或检测到运动时，中止当前收尾并保留停止待确认；停止恢复流程重新请求停止、核对静止后再处理，不自动恢复运动。取消意图在各阶段检查。完全断链时上位机不能保证停止帧送达，退出强制DI不是独立停机保证。

普通连续JOG不重复HOME收尾。其普通停止仍按ACK完成、保持JOG使能，不套用HOME静止与保持阶段。

## 模拟PP

PP到位核验可信参考和目标、准备模式及速度/目标后启动，基于反馈确认到达。全升/全收为软件端点定位。允许从范围外返回1–182cm内目标，保留物理限位、可信参考和单次位移限制；报警仅提示。实机PP旧强制DI路径尚未完成兼容核实，继续禁用，不能把HOME成功直接推广到PP。

## 手动报文执行

明确确认的手动写直接接管并取消普通任务，不先自动停止，不受检查、位置参考、报警、限位或普通软件急停门禁。后台仍读取与显示反馈，但手动期间不会因报警、失鲜或通信错误自动发停止或复位。失败保留“结果未知”，不自动重发、不永久锁定后续手动请求；新手动写不解除普通运动急停。

用户主动点击停止、软件急停或结束手动仍发停止请求，并取消未发送的旧请求。停止通道跟随最近手动控制字：P0D-08使用总线停止，P0D-11使用JOG停止；没有新控制字时沿用既有驱动上下文。ACK不证明机械静止，不能据JOG抓包推断P10的实机停止结果。连接切换拒绝把旧请求送往新设备；格式、CRC和响应匹配继续校验。

## 通信与实际反馈边界

网络串口服务器透传完整RTU帧；请求串行，超时/坏CRC/异常应答不能当作成功。自动流程只在明确停止恢复路径重试停止，不盲目重发任意原始写入。前后端断联通过动作心跳停止本工具点动；后端与设备断联通过异常处理请求停止，但断链时不能保证停止帧送达。

P0B-04现有到达/回零位、P0D-17/18及DI3不能确认功率级使能完成。手册未提供已明确核实的RS485失联自动停机配置，P0C-25是应答延时。ACK、主机超时、模拟通过均不是实际停机保证。其他主机引发的运动在纯观察状态下不被自动干预。

抓包证据支持1/17/33/65和0x4604的100/300rpm关系；实机连续JOG已由用户试用。正反向未静止接续的机械冲击、驱动器加减速行为、满载停止距离和失联保护仍需实机验证。所有离线验证均不得自动连接或控制真实设备。

用户实测P0D-11最低位为1的JOG命令停止续发约6～7秒后会失能；仅为JOG观察，不作为HOME或普通总线模式的断链停机保证。

## 回零失败601的人工恢复

Er.601（包括现场原码0xE601）出现后，自动流程请求停止并以实际转速/位置确认静止，随后结束pending_stop、保留故障和无效的位置参考，允许操作者点击“人工故障复位”。此阶段不执行HOME强制DI失能收尾、不写P0D-01；保留的是驱动器实际报警，不是界面人为锁存。正常成功HOME的自动收尾不受此例外影响。

只有操作者点击“人工故障复位”后，才在静止条件下复用上述完整HOME失能收尾，包括逐条读回、两段DI3等待和实验性最短保持；无论本次服务是否持有HOME使能标记、P03-07是否已读回0，都不能省略。随后实际读取P0B-34：

- 已为0：失能过程已经使报警消失，不再发送P0D-01。
- 仍为同一601报警：只发送一次P0D-01=1，再在stop_timeout_s内读取P0B-34确认清零，不用复位命令回显判断成功。
- 变为其他非零报警：记录实际变化，仍可执行本次人工请求的一次复位；结果以随后读回为准。读取失败、超时或复位后仍非零，不报清除成功，不自动重发或启动运动。

601清除后，在同一次人工操作中重新执行控制条件检查；检查通过且无软件急停才恢复操作条件，可直接再次点击“一键回零”。不自动启动回零，不恢复位置可信；新回零完成前PP仍不可用。恢复检查失败明确区分“601已清除”和“检查未通过”，提示剩余问题。软件急停不会被故障复位解除。

控制台home_timeout_s与驱动器Er.601不是同一个状态。仅控制台回零超时时，停止并收尾后通过“检查 / 恢复”重新核对，再由用户重新回零，不伪造601或无故发送故障复位。长行程应核对搜索速度和控制台超时配置；手册对驱动器P05-34/35的回零时限引用存在歧义，不自动修改这些参数。清警不消除实际机械、限位或超时原因。

## 停机或失能生效参数的共用操作约定

已实测的失能切换流程不仅用于HOME，也可作为其他参数操作前的共用步骤。当前记录的是后续复用设计与边界，不新增批量改参或自动恢复运动功能：

1. 请求停止，并通过转速与位置反馈确认静止；仅收到停止应答不能继续按已停机处理。
2. 按本章经现场验证的失能切换路径，逐条核对写应答与实际读回、DI3低/高变化和实验性保持；异常进入停止待确认，不继续写目标参数。
3. 按该参数的官方设定条件和生效条件写入，并实际读回核验。读回正确只证明保存值；若有独立的有效状态或行为判据，还须按该判据确认生效。
4. 完成检查后，由用户明确决定恢复控制或重新启动运动；参数操作本身不自动使能或续发旧运动。

“停机设定”约束允许写入的条件，“停机生效”约束新值何时参与运行，两者不能仅凭名称视为同一条件；实际含义应按该参数的官方说明核实。“再次上电生效”不能用软件停止、失能、故障复位或重新连接替代断电重上电。P03-07的现场现象和恢复结果是当前证据，不代表所有同类参数都已实机验证；存在手册冲突时保留不确定性，不按表格读回成功推断内部已采用新值。

## 回零速度与加减速度设置

“调试参数”提供P10-36搜索速度、P10-38爬行／查询速度（指令单位/s）和P10-40回零加减速度（指令单位/s²）三个独立输入框，对应home_speed、home_creep_speed、home_acceleration。空值表示沿用本次驱动器读回；不预填厂家默认值覆盖现场配置。填写值必须为正整数且不超出有符号32位编码范围；这不是机械安全上限，两项速度还须在启动前核对不超过实际P10-23。

保存仅持久化控制台期望值，重启加载优先于示例配置，不写驱动器；按已有流程重新检查，再显式启动回零时，先准备并逐项读回参数，再使能、最后启动。任一读回失败不得继续使能或启动。寄存器监视仍显示实际值，不能用期望配置冒充实际读回。P0C-13=0检查保持，电子齿轮不变。P10-40是加减速度而非加速时间。当前原生指令单位直接输入，不引入第二套单位换算。

真实HOME停止指令应答后未及时停止的问题仍待排查；开放配置不代表已验证更高速度或加速度，模拟测试不能证明实机停止能力。

## 全局停止与点动松手

顶部停止（不带intent_id）始终发送P0D-08=256，软件急停始终发送512，不依赖JOG历史状态；若当前仍处于本工具JOG上下文，随后补发P0D-11=1（普通停止）或65（急停）撤销专用点动请求。发起时取消旧意图与保活，待处理的点动停止可升级为全局停止。若总线停止应答失败仍尝试撤销点动，但整体保持停止待确认，不把部分成功当作完全停止。全局按钮通过转速和位置核对静止；急停保留主动锁存，不因报警放开策略而解除。

点动松手、保活超时保留原有专用停止和ACK确认，不额外等待静止影响连续点动。旧intent迟到松手不影响新动作。HOME从一开始就不走JOG分支。已有实测中256/512得到应答后HOME未及时停止的原因仍未查明；此次分流修正已通过模拟验证，不宣称已解决实机停止问题。

## 报警与操作者决策

使能、失能、普通运动请求不因已知或未知报警码而被控制台拒绝。报警与建议继续显示，驱动器是否接受命令或运动以实际反馈为准；这不证明驱动器覆盖所有风险。未知含义、未知复位能力不转化为软件门禁，也不据此自动丢弃位置参考。明确涉及位置参考失效的已知报警仍更新参考状态，定位需要可信参考。

人工复位允许尝试一次P0D-01，包括手册标注不可复位、未知码、限位仍有效的情况；手册能力属性仍保留。只根据复位后的实际读回报告是否清除，不自动复位、不自动重发、不自动恢复运动。601保留已有专用人工失能恢复流程和故障原码；失败回零任务结束，但恢复按钮仍可操作。物理限位方向保护、通信与应答校验、停止待确认、用户主动软件急停和回零完成参考核对均独立保留。
