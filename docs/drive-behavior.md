# 驱动器实测行为与设计依据

本文件保存本项目长期需要的硬件知识，截至2026-11-18。按功能归纳结论，不作为操作日记。官方定义以[两份手册及校勘](protocol.md)为依据；《自动回零.txt》不是官方资料，不作为控制实现依据。原始抓包、完整TX/RX、截图与一次性脚本留在被忽略的运行目录或外部证据位置，不合入产品基线。

来源分为官方手册、官方软件USB被动抓包、调试工具以太网TX/RX、操作者现场观察和模拟测试。正确写应答、寄存器读回、DI状态、实际位移和声音分别表述，不相互替代。操作者已反馈本版“各功能测试ok”；这是现场功能验收反馈，不扩展为所有负载、断链和极限工况均已验证。

## 寄存器名称与地址

参数后缀为十进制，Modbus地址用十六进制表示。P0D-11的地址是**0x0D0B**；P0D-17是**0x0D11**，P0D-18是**0x0D12**。名字中的11与地址中的11不能混用。P0B-34的地址为0x0B22。指令中的1、17、33、65、128、256、507、511、512若未标0x均为十进制。

## JOG独立控制通道

官方软件通过USB COM4与驱动器通信，两次被动抓包确认：

| 功能 | 实际命令 | 证据含义 |
|---|---|---|
| JOG使能/保持且不要求运动 | P0D-11=1 | 不是P0D-17强制DI |
| JOG正/负方向 | P0D-11=17/33 | 在本机对应上升/下降；保持物理限位路径 |
| 停止JOG且保留使能给定 | P0D-11=1 | 连续点动不需要先65再1 |
| JOG撤销使能请求 | P0D-11=65 | 不能推广为所有运动模式的通用急停 |
| JOG速度 | 0x4604单寄存器 | 官方界面100、300对应写入100、300，单位rpm |

0x4604与P10-42不是同一速度通道；旧API中的pv键目前表示JOG速度档案。每次新点动先读取P0D-11，值不为1才发送1，随后17/33。不能根据历史写ACK跳过使能，也不能把读回1视为功率级使能完成。监视主值只展示03读回，写ACK仅辅助显示；二者不一致时保留证据，不用ACK填充成读值。

操作者观察到P0D-11最低位为1的请求若约6～7秒未续发，JOG使能会自动撤销。该现象仅在JOG观察到，不能推导为HOME看门狗、所有模式的通信超时停机或厂家保证时限。操作者另确认P03-07=1，以及P0D-17=1、P0D-18=507可维持较长时间使能；这里是使能而非失能，不能套用JOG的超时撤销现象。当前点动按住时有主机心跳和当前方向续发，松手/失焦/保活超时结束该动作；结束后的保活不得重新启动运动。

## 强制DI与实际限位

现场当前DI3功能1（S-ON），DI4功能14、DI5功能15。以本次接线和极性为前提：

| P0D-17 | P0D-18 | 现场观测 |
|---|---|---|
| 0 | 511或507 | 强制DI未启用；修改18本身不能证明实际输入已改变 |
| 0 | 511 | 外部磁铁触发开关可使P0B-03从0x3F变0x37（DI4低）或0x2F（DI5低）；JOG到下限位会停 |
| 1 | 511 | 物理开关变化不再反映到P0B-03，也未产生对应限位报警；不能认为物理限位路径仍有效 |
| 1 | 507→511 | 在本机DI3配置下产生强制DI3低→高变化，可参与使能/失能切换 |

最初在P0D-17=0时观察“18改变而B03不变”，只能说明强制选择尚未启用，不能据此否认强制DI会屏蔽物理输入。故普通JOG和HOME运动保持P0D-17=0；独立使能按钮及静止后的HOME恢复另按明确的强制DI流程执行。

下限位可能报950，也可能报952；外部磁铁触发下限位曾报950，真实下降到开关后也有不同代码。限位方向必须由当前DI及已知功能/极性确定，不能用报警文字替代。未捕捉到DI变化也不能证明没有短脉冲；高度0.35cm附近停下不足以判断是噪声，仍需波形或重复测量。

残留950时，JOG命令获得正确应答而无运动；操作者清除950后可恢复。界面因此提示“可能是驱动器内部仍在阻止运动，按需人工故障复位”。952尚无相同拒动因果验证，不能类推。

## 模式17回零：先参数、再使能、最后启动

现场有效顺序是P02-00=9、P10-03=6、P10-35=17、准备P10-36/38/40，再P03-07=1，最后P0D-08=128；运动期间P0D-17=0。曾成功使用搜索速度20000指令单位/s（当前N=10000时120rpm）。日常一键回零按[完整控制流程](control-flow.md#模式17一键回零)执行，不把此列表作为省略前置读取的脚本。

早期失败试验先写128、随后改变P03-07使能，设备降至机械端点并发生620，随后601。与成功顺序有差别，但不是证明失败唯一由时序导致。不能再以“有ACK”或“先启动再补使能”猜测状态。

模式17成功时观察到实际下限位触发、反向脱离，P0B-04由3变11（Bit3从0到1），最终位置及转速回到参考附近；过程中不要求出现950/952。不能证明驱动器模式17内部只识别952。主机用本次完成位、DI过程、位置和静止共同确认；约7.8秒仅为一次耗时，不是固定等待。

官方软件回零相关灰色面板不反映真实值，不能作为参数或状态证据。现场官方USB串口与以太网串口服务器最终接入同一驱动器485，测试时不能同时作为主站操作；USB抓包不能覆盖走以太网的回零事务。比较故障前后应使用同一完整以太网记录，不能把两个不连续来源拼成无缺口的指令流。

## P03-07读回0不等于实际失能

现场反复观察：P03-07从0写1可产生使能，随后写0虽读回0，电机使能声音仍在，官方软件和工具JOG均可能正确应答却不运动。断电重启可恢复；故障窗口报警可为0、DI可为0x3F，不是所有无运动都由控制台门禁造成。

手册将P03-07列为停机生效，485案例解释停机设定需断使能。观察与“新值已保存但尚未满足实际采用条件”相符；该解释不是已取得驱动器内部状态的证明。P03-07本身是DI3极性参数，不是通用即时使能寄存器。

操作者在P03-07=0且仍使能时执行P0D-17=1、P0D-18=507、P0D-18=511、P0D-17=0，恢复实际失能与JOG；确认全过程未运动，退出后磁铁验证限位有效。单独在回零后执行“17=1→18=511→17=0”未必解除残留使能；先点击独立使能再失能可以恢复，说明需要保存已验证的切换过程，不能只追求最终寄存器值一致。

仅逐条03读回、仅等待DI3低→高仍曾失败。对照成功的手动按钮操作，507约保持3.68秒且存在额外停止请求，无法单凭这一记录认定唯一原因。操作者允许加入可配置最短保持；当前自动收尾采用507至少4秒、511至少0.2秒，期间持续核对给定、DI3、位置和转速，而非盲目睡眠。

一次授权自动HOME收尾中，实际507保持约4.049秒、511约0.314秒，最终17/18读回0/511、转速0、报警0，操作者明确确认使能声音自动消失。随后操作者对当前版本各功能测试反馈通过。此结果支持当前流程可用，但4秒/0.2秒不是厂家最短时限，声音消失也不是已发现的功率级状态位。完整顺序只在[控制流程](control-flow.md#home静止收尾与实验性保持)维护。

独立按钮为各自用途保留明确流程：使能17=1→18=507并保持；失能先确认静止，再17=1→18=511→17=0。HOME残留状态使用带507低电平与保持的完整恢复，二者不可混为一谈。

## 601故障保留与人工恢复

原始读回0xE601对应Er.601，含义为回原点失败。P0D-01=1是**故障复位**，不是位置复位，也不是清编码器或重新设零。

现场601下直接写D01虽正确应答，读回仍为E601；随后P03-07=0读回确认，再D01=1，报警清零且全过程未运动。这说明复位ACK不能证明清除，解除相关使能状态可能是恢复条件。另一次慢速HOME中，失能切换本身已使601消失，没有发送D01。

因此自动失败停机只确认静止并保留601，不自动执行会清警的HOME收尾。完整失能恢复绑定“人工故障复位”：失能后实际报警已零就不发D01；仍有报警则按人工请求单次尝试，并读回核验。不自动续发失败HOME、不自动建立可信位置，检查后由用户重新启动。不能用界面人为锁存一条601来掩盖驱动器报警已被自动清除。

慢速试验从约116.68cm开始，P10-36=2000指令单位/s，约100秒后出现E601并自行停下；操作者明确未按硬急停或断电。该持续时间是本次观测，不是已确认可配置的厂家超时常数。手册P05-34/35相关引用存在歧义，不自动写入。试验后P10-36恢复20000并实际读回；未因此自动提高加速度。

## 启动、停止与通信：尚未闭合的证据

同一次慢速HOME日志中，主机在启动后约2.392秒按“无运动/堵转”发停止，第一次位置变化约2.811秒、首次非零转速约2.946秒，随后约-12rpm。它证明该次启动诊断早于观测运动，不证明电机已机械堵转。当前JOG无运动只提示；HOME仍有独立启动、进展和超时检查，不能误称这些条件已全部去除。调慢速度时应同时审视这些诊断预算，不能把固定2秒当作所有速度的物理结论。

该试验中P0D-08=256和512均获正确应答，实际下降仍持续，最终约100秒由驱动器601停机。原因未确认；不能以ACK认定已停，也不能归因于JOG停止分支——当时HOME确实发了这两个总线值。

现有顶部停止始终发256，软件急停始终发512；有本工具JOG上下文时额外撤销JOG请求。点动松手保留专用快速停止。主机通过反馈确认全局停止；通信丢失时保留结果未知。后续“各功能测试ok”支持本版功能验收，但没有提供上述慢速异常场景的逐项复测记录，不能静默把该证据删除。

尚未从官方手册确认RS485断链自动停机设置或实际功率级使能完成状态位。完全断链时，上位机无法保证任何总线命令到达，退出强制DI也不是独立停机保障。JOG约6～7秒失能现象不能推广到HOME。

## 报警编码与操作者决策

| 原码 | 解释 | 证据等级 |
|---|---|---|
| 0xE601 | Er.601，回原点失败 | 现场读回与显示确认 |
| 0x6121 | Er.121，伺服ON指令无效故障 | TX/RX读得6121，操作者确认官方软件显示121 |
| 0xE950 / 0xE952 | 950 / 952限位警告 | 现场多次观察；方向仍以DI为准 |
| 0x6620 / 0x6B00 | 620 / B00 | 旧实现显式别名；编码说明仍保留来源限制 |

6121的具体触发根因尚未确定，不能因为刚调整了回零参数就认定是速度或加速度导致。手册121建议检查DI/VDI功能与有效电平。软件只对有依据的完整原码建立显式映射，不普遍剥掉任意首位6或E。

操作者要求故障恢复判断由现场人员作出：已知/未知报警均不按报警码单独禁用使能、失能、运动请求或人工尝试复位；手册能否复位是说明，不是按钮白名单。非零报警可人工尝试一次D01，不自动复位或重发；实际未清除就如实报告。物理限位、通信正确性、用户软件急停锁存和可信定位参考独立保留；不由未知码擅自推断位置丢失。

用户曾将P03-02、P03-04、P03-12分别改为18、19、34，用于后续外部按钮功能，随后官方JOG正常。这不能证明这些DI设定必然导致先前JOG故障，也不授权工具自动改写它们。当前工具不为恢复JOG初始化DI功能。

## 参数生效、持久化与机械换算

已验证失能切换可作为要求停机/失能生效参数的共用操作能力：先确认静止，复用完整失能流程，再按具体参数条件写入和核验，由用户明确恢复控制。不能把“停机设定”“停机生效”“再次上电生效”混为一谈；最后一种仍须满足重新上电条件。实测P03-07案例不能当作所有参数均已实机验证。尚未实现的通用改参器不写成已完成功能。

P10-36/38/40分别为搜索速度、爬行/查询速度及回零加减速度。页面保存期望值，下一次HOME准备时逐项下发并03核对后再使能；空值沿用本次驱动器读回。保存及重启加载不改电子齿轮、不启动运动、不把期望值冒充实际值。P0C-13仍只读，不为保存速度频繁写EEPROM。

沿用此前两点现场校准：开关间实际行程183.7cm、计数差5113931，L/N=0.00003592148583936702cm/指令单位；取N=10000得到控制台L=0.35921486cm/转。原L=0.35少算4.712415cm。软件下限1cm、上限182cm，校准上开关坐标约183.656cm，余量约1.656cm。两点测量只确定比例，不能独立证明机械导程或电子齿轮；6mm导程配机械传动比只是候选解释，不修改驱动参数来凑比例。公式和来源以[校准说明](calibration.md)为准。
