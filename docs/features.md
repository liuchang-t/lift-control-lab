# 功能、接口与行为差异

候选实现只覆盖升降杆，不包含云台、视频或机器狗业务。冻结原平台基线用于模拟对照；本工具的 API、配置和网页不承诺原平台逐字节兼容。

## 功能边界

| 功能 | 当前行为 |
|---|---|
| 启动 | 默认真实设备且断开，不创建真实通信；显式保存的模拟选择仍可恢复并自动运行模拟器 |
| 连接设置 | 页面保存模式、主机、端口、从站、超时；下一次显式连接生效，无需重启；真实连接需确认 |
| 检查 / 恢复 | 设备条件预检及故障后恢复，不是权限获取，不自动运动或回零 |
| 基础JOG | P0D-11=1/17/33/65，速度0x4604整数rpm；无回零/位置可信/软件高度范围门槛 |
| P0D-17/18使能/失能 | 静止后执行各自强制DI序列，每条03核对；报警不单独封锁；给定与实际功率级状态分开 |
| P03-07使能/失能 | 独立写1/0后读取；不附加停止、预检或强制DI序列 |
| 故障复位 | 单次D01=1后读取P0B-34；不附加601恢复或预检 |
| 停止定位 | 全局正常停止256，确认静止后共用失能收尾；停止待确认期间不启动新普通运动 |
| 顶部停止/急停 | 固定发送P0D-08=256/512；有JOG时补充撤销请求；实际反馈确认静止，急停保留用户锁存 |
| 连续点动 | 每次读取P0D-11，非1才使能；停止以正确应答完成，不等待静止，不循环失能/使能 |
| 点动保护 | 实际DI限制方向；所有报警只提示，不单独锁定；松手、动作心跳和通信保护保留 |
| 点动无运动 | 仅诊断，不锁定或自动停止；同时存在950时建议人工复位，952不作同等推断 |
| 模式17HOME | 实机按参数→P03-07=1→128顺序实现；运动中不强制DI，静止收尾采用实测失能序列 |
| PP定位 | 真实及模拟开放；P03-07使能后单次绝对启动3，运动中P0D-17=0 |
| 目标高度 | 可信参考、目标范围和实际方向限位检查；允许从软件范围外返回范围内目标，支持软件范围内全行程 |
| 定位完成 | Bit0到位、位置误差、低转速及连续两次位置稳定共同确认；pp_tolerance_cm默认0.05cm |
| 定位诊断 | 显示目标、误差和状态；无运动不自动锁定、复位或重启 |
| 回零确认 | 实际下限位触发/释放、本次完成位、位置和转速；不要求950/952，无固定完成延时 |
| 速度与参数 | PP/JOG独立cm/s速度；统一换算，原子保存；重启不恢复运动或位置可信度 |
| 报警 | 原码、手册解释与建议；未知码保留原码；已知/未知均可人工尝试复位，不按报警码锁定操作、不自动重启 |
| 寄存器 | 快速保护采样、动态轮转、固定配置按需读取；硬件R/W属性与读/写应答分开 |
| 手动485 | 自动CRC，03/06/10；确认写直接接管，不受普通运动门禁；不自动停止、复位或重试 |
| 日志 | 20,000条缓存、暂停固定视图、清空和导出；重启清空内存记录 |
| 私有客户端 | 共享后端，无独占租约；停止优先和旧动作取消机制保留 |

当前交付参数为软件范围1–182cm、行程183.7cm、机械比例0.35921486cm/转。配置加载顺序为默认值、启动文件、页面参数保存、连接保存；后者覆盖前者。速度档案按设备身份保存，旧键 `pv` 对应 JOG。负载只展示原码：`load_raw`为uint16，`load_signed`为int16解释，`load_percent=null`、`load_scale_verified=false`。

## HTTP

默认地址 <http://127.0.0.1:8765>。POST要求 `X-Patrol-Client-Id`，跨站写拒绝。标识用于关联请求，不是独占控制权。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET / POST | `/api/config` | 脱敏配置 / 停机时保存允许的参数；仅PP加减速度和定位容差变化保留参考与检查状态，其他配置变化撤销 |
| GET | `/api/connection` | 当前连接、保存目标、连接状态和错误 |
| POST | `/api/connection/save` | 保存下一次目标；兼容POST `/api/connection` |
| POST | `/api/connection/connect` | 显式连接；真实设备要求 `confirm_real` |
| POST | `/api/connection/disconnect` | 本工具活动任务先停止；纯监视只断开 |
| GET | `/api/status` | 缓存状态；兼容 `/api/devices/lift_pole_1/lift/status` |
| POST | `/api/arm` | 检查 / 恢复，实机需 `hardware_confirmed:true` |
| POST | `/api/control` | 升降命令；兼容 `/api/devices/lift_pole_1/lift/control` |
| GET | `/api/readiness` | 缺失条件、当前诊断、恢复步骤与拒绝原因 |
| GET | `/api/registers`、`/api/parameters` | 观测缓存/参数；断开时不隐式连接 |
| POST | `/api/registers/refresh` | 逐块真实03读回；运动与接管也可刷新，返回成功数量及逐项错误 |
| GET | `/api/logs` | 当前保留的事件与报文 |
| POST | `/api/logs/tail`、`/api/logs/clear` | 增量读取 / 清空缓存 |
| GET | `/api/events` | SSE状态更新 |
| GET | `/api/manual/status` | 手动写接管状态 |
| POST | `/api/manual/transaction` | 完整RTU帧；写需 `confirm_write` |
| POST | `/api/manual/exit` | 停止并结束手动接管 |
| POST | `/api/inject` | 仅模拟开发测试，实机拒绝、页面不展示 |

旧 `/api/devices/lift_pole_1/lease` 及其 `acquire/renew/release` 接口只提供兼容状态/无操作，不抢占、不续期、不因租约停止。

常用控制请求：

```jsonl
{"action":"up","intent_id":"每次按下的新UUID"}
{"action":"heartbeat","intent_id":"本次按下的UUID"}
{"action":"stop","intent_id":"本次松开的UUID"}
{"action":"stop"}
{"action":"set_speed","mode":"pv","speed_cm_s":0.35}
{"action":"set_speed","mode":"pp","speed_cm_s":1.05}
{"action":"estop"}
{"action":"reset_fault"}
{"action":"servo_enable"}
{"action":"servo_disable"}
{"action":"servo_p03_enable"}
{"action":"servo_p03_disable"}
{"action":"home","confirm_homing":true}
{"action":"goto","target_cm":10}
{"action":"min"}
{"action":"max"}
```

正常控制接口的HOME、goto、min/max在实机与模拟开放；明确确认的原始手动帧不受该接口限制，其实机效果须独立核验。stop带intent_id表示点动松手，不带表示全局停止；estop始终全局。心跳只延续已有动作，不能启动；迟到的旧意图停止不能打断新点动。无模式的旧 `set_speed` 拒绝；`goto.height` 仅为相对 `travel_cm` 的百分比兼容输入，仍验证软件范围。候选不接受旧 `set_retracted_zero`。`max_move_pulse`仅保留后端配置兼容并从页面调试JSON隐藏，候选定位不再以该值限制单次行程。收拢、展开使用保存的PP速度；`pp_tolerance_cm`在页面“调试参数”JSON中编辑，通过`/api/config`保存并在重启后加载。

直接按钮的请求及结果详见[显式寄存器操作](control-flow.md#显式寄存器操作)。`details.operator_result`包含action、address、value、write_ack、read_address、read_value、read_error及时间；复位结果另含alarm、cleared，P03-07结果另含matched。写应答失败返回接口错误；读回失败或报警未清除保留操作结果，由这些字段区分。`ok`表示接口处理完成，不表示故障已清除或实际使能已完成。

状态包含 `online/control_mode/implementation/details`；details提供高度、速度、期望速度、报警建议、可信参考、参数观测和停止状态。`motion_notice/motion_advice` 是诊断，不等价于故障锁定。950无运动建议随运动恢复、动作结束或950消失清除；物理限位停止提示在有效新反馈确认脱离后清除，历史日志保留。

## Bridge、MQTT与冻结基线

Bridge默认关闭，启用后使用 `X-Patrol-Bridge-Token` 或 Bearer token，支持health、snapshot、lift/status、lift/lease、lift/control。不向Bridge开放HOME、故障复位、max/min和旧设零操作；仅提供升降设备数据。共享客户端不取消Bridge的启用和token边界。MQTT为可选状态发布，MQTT3.1.1 QoS0、无TLS。

冻结基线仅模拟，保留原比例速度、人工零点及已知缺陷；不支持候选HOME、复位和独立速度。原UI证据不运行。模拟模型不能证明实机惯性、开关响应、自锁承载、驱动器软限位或断网停机能力。实机HOME不同工况重复性、PP兼容边界与未验证事项见[验证说明](validation.md)。

## PP与HOME共用失能收尾

PP与HOME静止收尾采用逐条给定读回、DI3低/高电平等待及可配置的最短保持。home_enable_hold_s默认4秒、home_disable_hold_s默认0.2秒，可在页面调试参数保存并在重启后保持。上述数值为现场试验采用的配置，厂家最短时限及功率级完成判据尚未确认；完整顺序、超时和取消处理见[指令流](control-flow.md)。

通信失败按整体停止恢复处理，不以退出强制DI代替实际停机。完全断链时上位机不能保证停止命令送达；实际功率级状态及恢复效果仍须实机核验。

## P0D-17/18独立使能与失能

P0D-17/18按钮取消旧收尾意图，独立请求停止并确认实际静止，不先执行旧完整收尾。独立“使能”按钮随后依次执行P0D-17=1、P0D-18=507，并保持强制DI；独立“失能”按钮先停止并确认实际转速/位置静止，再依次执行P0D-17=1、P0D-18=511、P0D-17=0。每步复用强制DI写入/03实际读回核对，正确才执行下一步，不以后台轮询或写回显替代；失败中止当前序列并进入停止待确认。按钮不发送JOG使能命令，不启动运动；不改变基础JOG或HOME自身的使能方式。给定读回一致不证明功率级完成。

## 直接寄存器按钮

故障复位按钮只发送一次 `P0D-01=1`，随后读取 `P0B-34`，分别显示写应答和当前报警。按钮旁提示“复位前先失能”，不自动停止、失能、预检或重发；无报警、未知报警及601均可由操作者发送。独立P0D-17/18按钮保留，另提供P03-07使能（写1）与失能（写0），各自实际读回P03-07。P03-07读回是给定值，实际使能是否改变仍需观察驱动器反馈。

## 现场恢复操作

物理限位有效时PP反向启动可能被驱动器拒绝，正确950也不保证启动。上限位有效时先JOG下降脱离，当前HOME入口禁止该条件；下限位有效时可JOG上升或按模式17现有条件HOME。DI恢复且参考可信后再PP，不新增全方向PP软件门禁。

上限950、下限952可能相互错报；方向始终以实际DI为准。仅在对应DI有效且警告错位时，人工D01一次或多次曾可纠正报警方向；其他时机无效原因未知，不自动清警。HOME已因601自动终止并自行失能、D01无效时，现场有效操作为P0D-17/18组合使能清警后再失能。故障复位按钮仍只发送单次D01。

HOME下限位附近曾出现约4～5次掉电重启，P10-03恢复为3（PV），根因未知。操作者重新检查连接及反馈，执行检查 / 恢复后重新启动HOME；历史完成位不作为成功判据。具体步骤见[控制流程](control-flow.md#回零失败601的人工恢复)，证据见[驱动器实测行为](drive-behavior.md)。

## 回零参数调试

调试参数面板可分别保存P10-36搜索速度、P10-38爬行／查询速度和P10-40回零加减速度，页面单位分别为cm/s、cm/s、cm/s²。留空沿用驱动器当前值。保存不下发，下一次回零准备阶段逐条写入并读回后才使能、启动；配置重启保留。实际寄存器值仍以监视读回为准。详见[控制流程](control-flow.md#回零速度与加减速度设置)。

## PP加减速度设置

页面分别设置PP加速度、减速度和急停减速度，单位cm/s²。配置键为`pp_acceleration_cm_s2`、`pp_deceleration_cm_s2`、`pp_emergency_deceleration_cm_s2`，默认均为空；空值沿用驱动器本次读值，非空值在下一次PP准备时换算为cmd/s²，写入P10-27/29/31并逐项实际读回。保存只更新控制台配置，不立即写设备。仅改变这三项与`pp_tolerance_cm`时保留当前可信参考和检查状态，参数保存仍需确认静止。

HOME配置API接受`home_speed_cm_s`、`home_creep_speed_cm_s`、`home_acceleration_cm_s2`，统一换算后保存到旧`home_speed`、`home_creep_speed`、`home_acceleration`字段，旧字段继续表示cmd/s或cmd/s²。配置响应的`home_display`提供派生的页面单位值，不改变既有配置文件单位语义。

## PP目标高度状态

`details.positioning`包含status、target_cm、error_cm、tolerance_cm和detail；误差为目标高度减去当前高度。定位任务保存请求目标并显示当前误差和状态。新启动依次准备参数、使能给定、发送绝对定位；完成后执行共用停止确认和失能收尾。无运动只生成事实诊断，不触发故障复位或短时无运动锁定。

`already_at_target`表示请求时当前位置已进入配置容差且已确认静止，本次没有发送定位启动。实际启动的任务依据本次新鲜反馈完成：P0B-04 Bit0=1、目标误差不超过`pp_tolerance_cm`、转速绝对值不超过1rpm、连续两次位置稳定。不要求采样到Bit0先清零后置位；短位移可能在两个采样间完成。

“停止定位”执行全局正常停止256，确认静止后进行共用失能收尾；pending_stop期间拒绝新普通运动。独立P0D-17/18、P03-07和故障复位按钮保留人工介入入口，不因旧收尾失败拦截。接管撤销旧总线使能任务所有权，后续JOG不自动恢复旧失败收尾；这不等于实际失能确认。软件范围、可信参考、物理方向限位及通信正确性检查继续执行。报警码不单独阻止请求，清警和独立使能/失能入口保持原行为。PP定位、速度与加减速度设置、正常停止及软件急停已有现场验证；反方向限位有效时的PP拒动原因尚未确定，验证记录见[验证状态](validation.md)。

定位状态按任务与反馈分别定义：

| status | 含义 | 实际静止或收尾结论 |
|---|---|---|
| already_at_target | 请求时已在目标容差内，未启动 | 已确认静止，本次未执行定位启动 |
| stopping | 已请求停止，停止确认及收尾处理中 | 尚未报告停止流程完成 |
| cancelled | 旧任务已取消或由人工接管 | 不表示已确认实际静止 |
| stopped | 实际静止已确认 | detail说明收尾结果；601保留时明确收尾未执行 |
| complete | 定位完成 | 到位条件满足且收尾已结束 |

停止请求等待预算耗尽时，若停止命令已应答且反馈仍有效，返回当前pending状态，不以正常减速尚未结束返回503。后台继续确认；`StopNotSettled`表示反馈暂未稳定，保留可信参考，不将其归为通信失败。通信异常仍按停止待确认处理。

运动中提交新目标或点击展开、收拢会停止当前任务；检查 / 恢复后需重新手动启动，不自动接续。现场已确认对应方向DI有效时禁止启动、运行中触发时停止。950/952与实际方向均可能不一致，方向统一依据实际DI，软件急停的人工锁存仍保留。

目标到位条件满足后仍须完成停止确认与收尾，不能直接将该中间阶段显示为complete。601保留时，即使已确认静止，也仅报告stopped及“601报警保留，失能收尾未执行”。
